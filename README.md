# Machine learning phishing email detection system

ITRI625 project: a deep-learning model that classifies emails as **phishing** or **legitimate**. The model is served through a **FastAPI** endpoint and used from a **Tkinter desktop app**.

| Component | Technology | Location |
|---|---|---|
| Model + training, metrics, graphs, XAI | PyTorch BiLSTM, scikit-learn TF-IDF + Logistic Regression baseline | `notebooks/02_model_training.ipynb` |
| Shared preprocessing + model code (written by the notebook) | Python | `phishing_core/` |
| REST API | FastAPI + Uvicorn | `api/main.py` |
| Desktop application | Tkinter (standard library) | `app/desktop_app.py` |
| Saved model artefacts | `.pt`, `.json`, `.joblib` | `models/` |
| Metric log + figures | CSV, PNG | `results/` |
| Web frontend (optional, in progress) | React + Vite | `frontend/` |
| Hosting (bonus) | Docker | `Dockerfile` |

## 1. Setup (Windows)

```powershell
# from the project folder
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Mac/Linux: `source .venv/bin/activate` instead of `.venv\Scripts\activate`.

> If `pip install torch` fails on a very new Python version, create the venv with Python 3.12 instead: `py -3.12 -m venv .venv`.

**Dataset:** put `CEAS_08.csv` in `data/`. It comes from the Kaggle *Phishing Email Dataset* collection. Any other CSV from that collection with `subject`, `body` and `label` columns, such as `Nazario.csv` or `Nigerian_Fraud.csv`, is picked up automatically when it's in `data/`.

## 2. Train the model

Open `notebooks/02_model_training.ipynb` in VS Code or Jupyter and choose **Run All**. On a laptop CPU this takes roughly 10–25 minutes. The notebook:

1. loads and cleans the data, and removes duplicate emails (to prevent leakage)
2. makes a stratified 70/15/15 **train / validation / test** split
3. trains the **TF-IDF + Logistic Regression** baseline
4. trains the **BiLSTM** and logs all metrics after **every epoch**:
   - loss, accuracy, precision, recall, F1, AUC-ROC and PR-AUC
   - saved to `results/metrics_log.csv`
5. uses **early stopping** (patience = 3 on validation loss) and restores the best weights
6. plots the loss/accuracy curves, ROC, PR curve, confusion matrices and threshold trade-off; the figures are also saved in `results/figures/`
7. saves the model to `models/` and runs **XAI**: logistic-regression weights, occlusion and LIME

> **Commit the notebook with its outputs.** Outputs that aren't visible cost 10 marks.

## 3. Run the API

```powershell
uvicorn api.main:app --reload
```

- Interactive docs: <http://127.0.0.1:8000/docs>
- `GET /health`: model status and test metrics
- `POST /predict`: analyse one email

```json
{ "subject": "Your account is suspended", "body": "Verify your password at http://...", "model": "bilstm", "explain": true }
```

Response: `label`, `probability`, `threshold`, `top_tokens` (word-level explanation), `indicators` and `latency_ms`.

## 4. Run the desktop app

With the API running, open a **second terminal**:

```powershell
.venv\Scripts\activate
python app/desktop_app.py
```

In the app you can:
- paste an email, **Load .eml file**, or **Load sample** (sample `.eml` files are in `samples/`)
- choose the BiLSTM or the baseline model
- click **Analyse email** (or press Ctrl+Enter) to get the verdict, the probability, and the influential words highlighted in the email

## 5. Hosting (bonus)

```powershell
docker build -t phishing-api .
docker run -p 8000:8000 phishing-api
```

The same image can be deployed to Render, Railway or Hugging Face Spaces (Docker Space). Once it's deployed, put the public URL in the desktop app's **API URL** box.

## Working together (version control)

- Pull before you start: **Fetch origin → Pull** in GitHub Desktop.
- Work on a branch per task, e.g. `wayne/model-training` or `asemahle/data-prep`, and merge through Pull Requests.
- Don't both edit the same `.ipynb` at the same time, because notebook merge conflicts are painful. Each person owns their notebook or file.
- Commit small and often, with clear messages, e.g. `Add early stopping to training loop`.
- The shared code in `phishing_core/` is written by the notebook. Change it in the notebook, re-run, then commit both.
